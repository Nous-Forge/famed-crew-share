# Content provenance

The November 8 source-derived snapshot retains 16 original skill names and printed Dungeon text beside separately labeled prototype costs, targets and effects. Its four roles are Captain, Pathfinder, Lorekeeper and Vaultwarden.

The earlier source record names the FAMED design drafts, Full Game 5.2 and Dungeon Mode 3.0 guides, skill-card CSV and designer decisions. Private originals are not all distributed here. Hashes in the dataset identify the earlier producer inputs, not a new check of moving source files.

The improved command reads the included GDD v8 review excerpts and 16 verbatim rows extracted from the original skill CSV. It verifies the packaged hashes and evidence passages, extracts the provisional boss, crew roles, prototype hand size and role writing directions, and compares the prototype configuration with the selected design facts. The card extraction records the verified original CSV hash and physical line/record references. It excludes private absolute paths and external art URLs.

Card output is generated from original names and Dungeon text, a readable normalization and separately labeled prototype templates. Crew event lines use short authored templates grounded in the four role directions. Boss output uses the labeled prototype configuration. This is source-conditioned deterministic composition, not fresh model generation.

The artifact critic reads the actual draft payloads, compares all 16 card identities and printed text with the original CSV extraction, checks prototype fields against configuration, checks four speakers/event shapes, and checks boss/rules fields. Repairs use exact source values only. Uncertain identities or undocumented rules hold release. Fault demonstrations are explicit opt-in runs, preserve the flawed draft files and write corrected outputs separately. Actual final files are re-read and checked before release.

The selected GDD passages are included in docs/game-design/FAMED-GDD-source.txt; their original line references and source version are in content-contract.json. Those excerpts are not a complete GDD. The complete earlier review remains outside this package because its build and operational status has since changed. Runtime checking does not prove tabletop semantic fidelity, tone, full lore, balance or canonical website facts. Original unresolved card templates remain visible. No live model or deployed retrieval system is required.

Crew Report 14B retains the November 3 report. Its nine-crew comparison, charts and schedule descriptions are historical. They do not describe current November 8 operations. The ten later demos share two implementations. Missing per-game token and dollar measurements remain unknown. Nothing in this package installs or starts the historical studio automation.
